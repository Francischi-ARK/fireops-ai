# 合成警情核实与调派规范

## 业务边界

- 设备火警信号不是警情。信号只能由人工核实为“确认警情”或“排除信号”；只有确认结果可以生成一条合成警情。
- 所有页面和接口必须标注模拟角色、合成数据及未连接 119，不得让演示数据看起来像真实告警或真实调派。
- PostgreSQL 是状态真相源，时间线只追加合法业务动作，SSE 只负责通知页面重新读取持久化状态。

## 状态流

1. 信号：`pending → confirmed | dismissed`。相同结果重试幂等，冲突终态返回 409。
2. 警情：`pending_dispatch → dispatched → acknowledged → enroute → arrived`。
3. 站点：`available → awaiting_ack → assigned → enroute → on_scene`。
4. 调派只能发给覆盖企业辖区且当前可调派的虚拟消防救援站；跨辖区返回 422，站点忙或重复冲突调派返回 409。
5. 到场后可提交一次首报。现场情况为 1–300 字；到场前提交、冲突重试均返回 409，相同内容重试幂等。

## 页面职责

- 总队接处警台：设备信号核实、合成警情队列、辖区力量调派、状态跟踪和时间线。
- 救援站终端：只显示本站已分配任务，提供签收、出动、到场和首报动作。
- 首战提示只读取已存储的合成地址、危险源、入口、水源和消防设施字段；缺失项显示未知，并注明仅供辅助、不替代现场指挥。

## 验收

- 确认信号后只生成一条警情，排除信号不生成警情。
- 合法调派和站端动作各写入一次时间线，非法跳转不改变任何状态。
- 另一个已打开页面在两秒内看到变更；刷新或重连后仍能读取完整状态和时间线。
- 新增成功 JSON 响应和 SSE 数据事件包含 `is_simulation: true`、`external_system: "none"`；保活和错误响应除外。
