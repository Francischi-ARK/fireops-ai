# 技术架构说明

> 对应手册附录「技术架构说明」：模型选择、Agent 架构、工具调用方式、知识增强、多轮上下文、数据处理流程、系统架构图。

## 1. 系统架构

```text
响应式浏览器工作台（原生 HTML/CSS/JS，桌面指挥 + 手机确认 + Copilot 页）
  │  fetch / SSE
  ▼
FastAPI 应用（fireguard_backend）
  ├─ 领域 API：监测事件、信号核实、警情、调派、站端状态、首报、时间线
  ├─ Copilot API：/copilot/scenarios、/copilot/runs、/copilot/runs/{id}/approve
  │    │
  │    ▼
  │  CopilotEngine（单 Agent 编排）
  │    ├─ Scenario 模式：按场景夹具回放确定性计划（离线可复现）
  │    └─ Live 模式：一次 OpenAI 兼容调用（默认魔搭 Qwen）产出结构化计划
  │         │  失败（超时/无效输出/不可用）→ 自动回退确定性模板
  │         ▼
  │    ToolGuard（服务端守门：工具白名单 → 参数 schema → 状态检查 → 审批检查）
  │         ▼
  │    九个工具：信号上下文 / 场地信息包 / 维保记录 / 缺项检查 /
  │              核实草稿 / 站点推荐 / 调派草稿 / 角色简报 / 时间线记录
  ▼
PostgreSQL（企业、事件、核实、警情、调派、报告、时间线、copilot_runs）
  +
合成 CSV（维保、隐患、IoT 设备，demo-data/）
```

## 2. 模型选择与披露

- 默认：ModelScope 免费推理 API，Qwen 系列，`response_format=json_object`，temperature 0.2；
- 职责边界：模型只做意图理解、信息抽取、追问、摘要和工具选择；风险评分、状态流转、证据编号、权限与最终动作全部由确定性代码负责；
- 可替换性：OpenAI 兼容协议，换服务改三个环境变量；不依赖特定厂商私有能力；
- 闭源模型影响：Scenario 模式与全部测试不依赖外部模型，核心 Demo 可完全离线复现。

## 3. Agent 架构

- 单 Agent + 确定性工具层，无多 Agent 互话、无通用框架依赖；
- 模型输出固定 JSON 结构（intent / missing_fields / plan / tool_calls / evidence / draft_outputs / risks / approval_required / abstained），Pydantic 校验后才允许执行；
- 每次运行持久化到 `copilot_runs`：输入摘要、模式、模型名、状态、完整工具轨迹、证据、审批记录，支持复盘。

## 4. 工具调用方式

- 白名单：未知工具直接拒绝，不产生任何副作用；
- 参数：每个工具有独立 Pydantic schema，非法参数拒绝；
- 状态：调派草稿仅在信号经人工确认为「属实」后才允许生成；
- 审批：写时间线工具要求对应人工审批已记录；
- 证据：工具返回才产生证据编号；模型引用了工具没返回过的编号会被拦截并记录；
- 失败处理：工具失败进入轨迹并展示，不中断其余步骤。

## 5. 知识增强

- 采用「策展证据索引」而非向量库：企业档案、建筑预案、维保 CSV、信号记录按 ID 精确检索，证据可逐条核对；
- 检索策略：按企业/事件/辖区精确匹配，返回记录同时附带 `raw_ref` 来源编号；
- 升级路径：文档量或检索评测证明需要时再引入向量检索（当前规模为 5 家企业合成数据）。

## 6. 多轮与上下文管理

- 一次「运行」是无状态编排：输入（信号 + 上报文本 + 图片）→ 计划 → 工具 → 结构化结果；
- 多轮体现在业务流程而非对话：人工核实后用同一事件再次运行，Agent 根据最新状态（已确认/已建警情）推进到调派草稿与三端交付；
- 运行记录持久化提供可审计的「记忆」，不向模型暴露历史运行内容，避免上下文污染。

## 7. 数据处理流程

- 写入：合成信号经 `POST /monitoring/events` 入库并更新企业汇总指标（确定性规则）；
- 核实/调派：仅经既有领域 API，由人工触发，全部写入时间线；
- Copilot：只读工具 + 草稿工具，不直接修改领域状态；审批动作单独记录并落时间线；
- 所有接口返回 `is_simulation: true`、`external_system: "none"`；前端可将输入、工具轨迹、证据、人工决定和角色简报导出为 JSON 审计包。

## 8. 已知工程边界

- 无身份认证（本地演示）；SSE 为单进程内存广播；CSV 读取为全量扫描（演示规模）；
- 以上均有明确升级路径，不影响核心闭环的可复现性。
