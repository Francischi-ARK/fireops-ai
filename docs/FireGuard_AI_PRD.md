# FireGuard AI 产品需求文档

> 版本：V1.1  
> 产品定位：消防安全监测、监管与应急信息辅助平台  
> 当前阶段：产品结构重构与多角色原型验证  
> 数据范围：仅使用合成数据，不接入真实消防生产系统

## 1. 产品定义

FireGuard AI 面向消防救援机构、消防救援站、监督人员和重点单位。平台把日常消防安全监管与真实警情处置分开，同时复用企业、建筑、危险源、消防设施和数字化预案等基础数据。

首要目标不是建设通用聊天助手，而是形成可验证的消防业务闭环：

1. 总队汇总掌握重点单位消防安全状态；
2. 监督人员把异常线索转成检查、整改和复查任务；
3. 企业处理设备、维保和隐患明细；
4. 真实警情进入独立的接处警与救援站响应流程。

## 2. 术语与业务边界

以下概念不得在界面、数据模型或报告中混用：

| 概念 | 定义 | 典型来源 |
| --- | --- | --- |
| 设备火警信号 | 企业火灾自动报警系统上报的点位事件，尚未等同于消防救援警情 | 火灾报警控制器、消防物联网平台 |
| 设备异常 | 故障、屏蔽、隔离、离线、压力或液位异常等设施状态 | 消防设施和物联网设备 |
| 消防救援警情 | 经接报、核实并进入消防接处警流程的事件 | 119、联动平台、人工核实 |
| 企业消防风险 | 基于设施、维保、检查、隐患和数据质量形成的辅助分析结果 | FireGuard 风险规则 |
| 预警级别 | 法定或预案规定的突发事件预警级别 | 政府或授权应急指挥机构 |
| 应急响应级别 | 按预案启动、调整和终止的响应级别 | 授权指挥机构 |

设备火警信号只能触发核实任务或生成“待核实警情”，不能自动完成正式调派。企业风险等级也不能代替警情等级、预警级别或应急响应级别。

## 3. 用户与工作台

FireGuard AI 是一个平台，按岗位提供五个独立工作台。

| 工作台 | 主要用户 | 信息颗粒度 | 核心任务 |
| --- | --- | --- | --- |
| 重点单位监测中心 | 总队、支队管理和值班人员 | 辖区汇总，可下钻企业概览 | 监测趋势、发现异常、形成监管线索 |
| 消防接处警与指挥台 | 总队、支队指挥和值班人员 | 单起警情和力量状态 | 核实、调派、跟踪、续报和归档 |
| 消防救援站接警终端 | 辖区消防救援站 | 本站任务和现场必要信息 | 签收、出动、到场和情况反馈 |
| 消防监督检查工具 | 防火监督人员 | 检查对象、依据、证据和整改状态 | 检查、整改、复查和报告 |
| 企业消防管理工作台 | 企业消防管理人员 | 设备、点位、工单和责任人明细 | 巡检、维保、隐患闭环和预案维护 |

## 4. 四条业务闭环

### 4.1 重点单位监测与监管闭环

```text
企业设备与管理数据
  → 总队辖区汇总监测
  → 识别异常单位或趋势
  → 形成核实/监督检查任务
  → 监督人员检查
  → 企业整改
  → 复查确认
  → 总队查看闭环结果
```

总队工作台展示辖区级汇总，不直接承担企业工单编辑。监督检查是独立工具，企业整改在企业端完成。

### 4.2 消防接处警与指挥闭环

```text
接报或设备信号核实
  → 建立唯一警情
  → 信息核实与辖区匹配
  → 授权人员下达调派
  → 消防救援站签收
  → 出动、到场和处置反馈
  → 续报、提级或增援
  → 结束、归档和复盘
```

警情必须保留来源、核实状态、关键时间、操作人和完整状态变更记录。

### 4.3 消防救援站响应闭环

```text
收到警情任务
  → 确认签收
  → 查看建筑、危险源和预案
  → 确认出动
  → 途中接收更新
  → 到场反馈
  → 持续报告力量和处置状态
```

接警终端只显示本站当下需要的信息，不展示企业日常整改清单。

### 4.4 企业消防管理闭环

```text
设备事件/巡检/维保计划
  → 发现问题
  → 建立工单或隐患
  → 指定责任人与期限
  → 整改和提交证据
  → 企业复核或监督复查
  → 关闭并保留记录
```

## 5. 同源数据的分级展示

| 数据域 | 总队监测中心 | 企业管理工作台 |
| --- | --- | --- |
| 设备火警信号 | 辖区单位数、趋势、重复信号单位 | 控制器、回路、点位、时间和处置明细 |
| 故障、屏蔽、离线 | 故障率、长期未恢复单位、辖区排名 | 设备原因、恢复过程和维修工单 |
| 消防水系统 | 异常单位数、持续异常时长 | 泵、压力、液位和传感器读数 |
| 设施维保 | 完成率、逾期单位、维保机构趋势 | 月检、季检、年检、维修和更换记录 |
| 隐患整改 | 未闭环量、逾期率、重复隐患趋势 | 描述、责任人、期限、证据和复查记录 |
| 数据质量 | 在线率、数据新鲜度、断报单位 | 网关、接口和缺失记录明细 |

总队下钻到企业时默认显示企业概览。设备点位、人员信息和具体工单按权限开放并记录访问日志。

## 6. 下一版原型范围

下一版先验证产品结构和信息流，不接入真实 119、真实消防物联网或正式调派系统。

### 6.1 平台入口

- 展示五个岗位工作台；
- 根据演示角色进入对应工作台；
- 工作台之间不共享同一张混合页面。

### 6.2 总队重点单位监测中心

- 辖区重点单位总数和数据在线情况；
- 设备火警信号、故障、屏蔽、离线和维保逾期汇总；
- 未闭环、逾期和重复隐患汇总；
- 按辖区、行业、风险和数据新鲜度筛选；
- 异常单位排序与企业概览下钻；
- 从异常线索发起核实或监督检查任务。

### 6.3 消防接处警与指挥台

- 待核实、待调派、处置中和已结束警情队列；
- 警情来源、地点、类型、人员情况、危险源和可信度；
- 辖区与首战消防救援站建议；
- 人工确认调派、增援、提级和结束；
- 消防救援站签收、出动、到场状态；
- 事件时间线、续报和操作日志。

### 6.4 消防救援站接警终端

- 明显的声音和视觉提醒；
- 警情摘要、地址、人员被困和特殊危险；
- 建筑信息、消防水源、入口、平面图和数字化预案；
- 确认签收、确认出动、到场反馈；
- 通信失联或超时未签收提示。

### 6.5 消防监督检查工具

- 将现有检查、平面图、隐患、证据、整改和复查功能迁入独立工作台；
- 后续增加现场文字、语音和图片录入；
- 法规依据和正式文书必须经人工确认。

### 6.6 企业消防管理工作台

- 企业画像和设备状态；
- 设备事件、维保、检查和隐患明细；
- 整改责任、期限、证据和复核；
- 总队只能查看被授权的汇总和概览信息。

## 7. 警情最小数据与状态

### 7.1 最小字段

- 唯一警情编号；
- 接报时间、来源、地点和信息可信度；
- 事件类型、影响范围、人员伤亡或失联情况；
- 人员被困、危险物质、发展趋势和已采取措施；
- 所属辖区、调派单位、响应状态和关键时间；
- 当前指挥关系、支援请求和最近续报时间。

### 7.2 原型状态机

```text
待核实 → 已确认 → 待调派 → 已下达
→ 已签收 → 已出动 → 已到场
→ 处置中 → 已控制 → 已结束 → 已归档
```

状态不能任意跳转。撤销、退回、增援和提级作为有原因、有操作人的独立动作记录。

## 8. 借鉴 ICS 的能力

FireGuard 只借鉴适合中国消防业务的管理能力，不照搬北美组织名称和纸质表单：

- 统一术语和资源分类；
- 按事件复杂度扩展指挥组织；
- 明确事件目标、任务和责任人；
- 记录指挥权建立与移交；
- 跟踪人员、车辆、装备和物资状态；
- 维护通信方案、安全提示和事件行动计划；
- 支持多部门会商、联合指挥和资源请求；
- 保留事件简报、活动日志和复盘记录。

普通警情使用简化流程；跨区域、多部门或持续多个行动周期的事件再展开完整功能。

## 9. AI 使用边界

AI 可以：

- 从语音和文本中提取警情字段；
- 提示重复报警和信息缺口；
- 推荐辖区、预案、资源和检查重点；
- 生成态势摘要、续报草稿和报告草稿。

AI 不可以自行：

- 正式下达或撤销调派；
- 启动、调整或终止应急响应；
- 完成指挥权移交；
- 对外发布警情或预警信息；
- 自动关闭警情、隐患或执法事项。

上述动作必须由授权人员确认并留痕。

## 10. 下一版原型验收标准

- 五个工作台有独立入口和清晰角色；
- 总队监测汇总能够下钻到企业概览，但不出现企业工单编辑入口；
- 设备火警信号与消防救援警情使用不同名称、数据对象和状态；
- 一条合成警情能够完成核实、调派、签收、出动、到场和结束；
- 消防救援站能够看到与警情关联的建筑、危险源和数字化预案；
- 监督检查、企业整改和复查形成独立闭环；
- 每个关键动作显示时间、操作者和来源；
- 颜色不是唯一状态表达方式；
- 所有调派和应急决策均标注为模拟，不连接真实生产系统。

## 11. 开发顺序

1. 修订 PRD、产品路由、术语和数据边界；
2. 将现有混合页面迁移为独立的监督检查工作台；
3. 开发总队重点单位监测中心；
4. 开发消防接处警与指挥台及合成警情状态机；
5. 开发消防救援站接警终端；
6. 补齐企业消防管理明细页；
7. 业务流程经专家确认后，再接入后端、身份权限和真实数据。

## 12. 专家校验事项

- 设备火警信号转待核实警情的条件；
- 警情分类、辖区匹配、首战力量和增援规则；
- 接警、调派、签收、出动和到场的岗位权限；
- 超时提醒、提级、退回、撤销和结束条件；
- 指挥关系、现场反馈和续报字段；
- 总队可查看的企业数据范围和脱敏要求；
- 风险评分、异常阈值、统计窗口和缺失数据处理；
- 监督检查、企业整改和复查的责任边界；
- 新能源制造及锂电池场景的独立危险源模型。
