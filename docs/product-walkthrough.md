# FireOps AI 功能与演示说明

FireOps AI 面向新能源汽车工厂的消控室、EHS、处置班组、维保组和网格责任人。它把火警、设备故障、维保逾期和巡查隐患接入同一个事件与工单中枢，避免在主机日志、表格、纸质说明书和聊天群之间反复转抄。

## AI 在系统中做什么

AI 是证据辅助层，不是自动控制层。它负责识别任务意图、读取点位和车间上下文、检索维保记录与说明书、提示缺失信息、生成诊断和工单草稿，并把同一事件整理成不同岗位能直接使用的简报。知识检索会先核对设备型号和文档类型，再进行领域同义词归一化与关键词重排；结果包含文档、章节、页码、证据编号和匹配理由。

确定性代码负责 Modbus 解析、编号校验、证据引用、状态机和权限闸。高风险 API 使用服务端演示 RBAC：值班员负责核实与派单，班组负责处置和维修，网格责任人负责整改，巡查员负责派发隐患与复查，EHS 可全局演示。错误角色直接返回 403；允许的火警操作会把演示身份写入事件时间线。系统不会控制真实设备、自动启动灭火装置或自动拨打 119。

## 岗位工作台、流程监管与 Copilot

| 工作台 | 使用者 | 主要功能 |
| --- | --- | --- |
| 态势监测 `#/monitoring` | 消控室 / EHS | 从全厂 3D 总览进入电池车间二维消防平面；按状态、楼层和证据页签查看事件；注入合成火警或故障；3D 不可用时保留二维入口 |
| 报警核实 `#/incidents` | 消控室值班员 | 对待核实信号做人工确认或排除，建立处置事件并选择班组派单 |
| 流程监管 `#/workflow` | 值班员 / 班组 / EHS | 按事件显示当前步骤、责任角色和下一动作，并按权限把演示交接到对应工作台 |
| 班组工单 `#/station` | 处置班组 / 维保组 | 处置任务签收、出动、到场和首报；维修、维保工单确认、开工与完工 |
| 整改待办 `#/owner` | 区域责任人 | 接收巡查整改工单，开始整改并提交完成，等待巡查员复查；空状态不会伪造工单 |
| 防火巡查 `#/inspections` | 防火巡查员 | 图片与语音辅助生成隐患草稿，人工确认派发；扫描维保逾期；完成复查闭环 |
| 单元档案 `#/enterprises/:id` | EHS 经理 | 聚合点位、事件、维保、隐患、工单和证据编号，并带上下文跳转到下一岗位 |

Copilot `#/copilot` 是独立的 Agent 工作区，提供五个可离线复现的场景，也可以绑定中枢中已经存在的事件。评委首先看到按“输入、证据、工具调用、人工确认、结果”整理的运行记录，需要技术复核时再下载 `fireops-audit-pack/v1` JSON。派单后先停在交接页，由操作人明确切换到班组身份；不会在角色仍是值班员时直接跳进班组终端。

公开演示中，“模拟火警帧”和“模拟故障”只负责创建合成事件，不代替人工核实。只有待核实火警显示“进入 Copilot 核实处置”；误报可在监测页登记并关闭，故障和已恢复事件不会显示火警确认动作。

## 三条可演示闭环

### 1. 火警处置

`模拟火警帧 → 点位解析 → 人工确认火警 → 建立事件 → 人工派单 → 班组签收 → 出动 → 到场 → 现场反馈 → 值班员核验归档`

页面始终保留同一 `enterprise_id` 和 `event_id`。流程监管从数据库计算状态和下一责任人；归档后班组恢复可调派。设备火警信号不会被系统直接当成真实警情。

### 2. 故障与维保

`主机故障 / 维保逾期 → 手册与记录检索 → 工单草稿 → 人工确认派发 → 开始处理 → 完成核验`

故障不会进入火警处置链。未开始的工单不能直接完成，重复终态请求不会制造第二条记录。

### 3. 巡查整改

`现场图片与口述 → 隐患草稿 → 人工派发 → 网格责任人整改 → 完成工单 → 巡查复查 → 关闭隐患`

当前 Demo 使用合成图片目录与关键词规则识别，语音优先使用浏览器 Web Speech，不宣称生产级 VLM/ASR。接口已预留视觉 provider；图片不清、语音信息不足或 Live provider 不可用时，系统会拒答或显式回退，不会凭空创建隐患结论。

## 五个 Copilot 场景

| 场景 | 结果 |
| --- | --- |
| A 涂装作业相邻误报 | 给出误报倾向与证据，人工登记后不建处置事件 |
| B 电池车间确认火警 | 生成处置草稿与三岗位简报，人工确认后派单 |
| C 火警主机备电故障 | 检索说明书和维保记录，生成维修工单草稿 |
| D 数据不足 | 列出缺失字段并安全拒答，不创建工单 |
| E 气体灭火延时咨询 | 引用紧急停动知识，只给咨询，不提供远程控制动作 |

Scenario 模式完全离线。Live 模式使用 OpenAI 兼容接口。模型计划整体缺少密钥、超时或结构不合格时，界面会显示原因并回退到确定性计划；具体工具调用若越过白名单、参数或证据约束，会被守门逻辑拒绝，不执行该动作。

## 知识检索评测

`demo-data/knowledge_eval.json` 包含 30 道可重复测试，其中 28 道有标准证据、2 道应拒答。当前 Top-1 召回 96.4%、Top-3 召回 100%、无依据问题拒答率 100%。报告由 `PYTHONPATH=backend backend/.venv/bin/python scripts/evaluate_knowledge.py` 生成到 `docs/submission/knowledge-eval-report.json`。这些数字只代表当前小型策展知识集，不代表真实工厂泛化能力。

## 数据说明

所有企业、设备、事件、维保、隐患、图片和角色均为合成演示数据。3D 只用于定位和态势表达，业务事实以数据库记录与证据引用为准。
