# 复赛合成数据字典

本文说明 `demo-data/semifinal/` 下数据合同的字段、命名和边界。数据全部为合成演示数据，不来自任何真实企业。

## 文件用途

| 文件 | 用途 |
| --- | --- |
| `role_permissions.json` | 八类人类角色的页面可见性与动作权限合同，前端与后端鉴权以此为输入 |
| `site_spatial.json` | 厂区、建筑、楼层、工艺区、设备点位的空间层级与路线拓扑 |
| `scenarios/fire-confirmed.json` | 真实火警全流程演示夹具（接警到归档） |
| `scenarios/false-alarm-maintenance.json` | 误报转维保工单闭环演示夹具 |
| `scenarios/inspection-rectification.json` | 巡查隐患整改闭环演示夹具 |
| `legacy_map.json` | 旧 CSV（企业、点位、事件）到空间模型的对接映射，按位置关键词归到工艺区、楼层或外门 |

## ID 命名规则

- 角色与车间：小写蛇形，如 `control_room_operator`、`ws-battery`。
- 空间实体带前缀：`b-` 建筑、`z-` 工艺区、`d-` 外门、`id-` 室内防火门、`st-` 楼梯、`pt-` 设备点位、`fr-` 消防资源、`hz-` 危险源、`gate-` 厂区门、`sn-` 厂区路线节点、`bn-` 建筑内路线节点。
- 场景步骤：`fc-`（火警）、`fa-`（误报维保）、`ir-`（巡查整改）加两位序号。
- 证据引用使用 `类别/编号` 形式，如 `monitoring_events/FIRE-001`，属于合成引用，不指向真实存储。

## 坐标规则

所有坐标归一化到 0–100，原点在图纸左下角，x 向右，y 向上。工艺区用 `{x, y, w, h}` 矩形表示，路线节点用 `{x, y}` 加 `floor` 表示。跨楼层通过 `stairs` 中的节点对连接。厂区道路（`sn-`）与建筑外门节点（`bn-*-door-*`）之间有直接路线边，因此可以从厂区门连续计算到车间外门、室内防火门和目标点位。

## 角色权限边界

- 管理层只读：只能查看汇总、下钻和报告，禁止一切核实、派单、验收、关闭动作。
- 消控室值班员：接警、派巡查、确认或登记误报、调度消防力量、经授权确认设备操作、生成报告与归档。
- 防火巡查：现场核实、隐患上报、整改复查；复查通过才能关闭隐患。
- 专职消防队：真实火警处置与现场反馈；确认火警后进入处置，不再承担核实闸门。
- 车间 ERT：仅本车间或分配任务。
- 消防设施部门：故障审核、维保派单、验收与关闭工单。
- 维保单位：只能处理分配工单并提交验收，不能自行关闭。
- 车间对接人：仅本车间隐患，协调整改并提交证据，不能自行复查关闭。
- AI 不是角色：只生成草稿与建议，任何动作必须由上述角色人工执行。

## 场景状态路径

- 火警：`pending → confirmed → issued → acknowledged → enroute → arrived → first_report → closed`；误报为 `pending → dismissed`。
- 维保工单：`draft → approved → in_progress → done`，不允许 `approved → done` 跳步。
- 巡查整改：`draft → assigned → closed`；复查不通过退回 `assigned`。

## 合成数据边界

每个文件顶层都有 `is_simulation: true` 和 `external_system: "none"`。数据不含真实企业名称、地址、人员、图纸或生产数据；不含自动拨打 119、自动启动灭火装置、自动操作真实设备或 AI 自动确认火警的动作。消防泵房只存在于厂区级设施，原料仓区集中在立体仓库，不复制到各车间。

## 校验

```bash
node scripts/validate_semifinal_fixtures.cjs
```

脚本只依赖 Node.js 标准库，覆盖 JSON 可解析、ID 唯一与引用存在、角色齐全、步骤链无环、动作授权、状态迁移合法、车间布局互异、泵房与原料库未滥用复制、合成标记完整、无越权自动动作共十项检查。
