# FireOps AI 复赛平台优化路线

## Goal

让评委仅打开 GitHub Pages 就能看懂并操作 FireOps AI：先从工厂总览进入车间，再查看异常证据、完成核实与处置；页面不依赖本地后端，也不向普通用户暴露 JSON、英文状态或无法操作的占位控件。

## 当前里程碑 M1：评委可操作的公网主流程

### Acceptance Criteria

1. 当页面无法连接后端时，态势监测明确显示“评审演示模式 / 本地合成数据”，不得出现 `Failed to fetch`、`后端未连接` 或误导性的实时状态。
2. 在离线模式点击“模拟火警”或“模拟故障”后，事件队列、状态、历史记录和地图高亮在当前浏览器内更新，不得因网络请求失败而中断。
3. “全部 / 待核实 / 处理中”可筛选事件；空结果有说明和恢复入口。
4. “现场位置 / 信号趋势 / 联动设备 / 历史事件”均可切换，并显示与当前车间和事件一致的合成数据。
5. “全部楼层 / 3F / 2F / 1F”均可点击。火警点只出现在对应楼层，切换楼层后标题、设备摘要和点位同步变化。
6. 态势监测默认先显示工厂总览。工厂总览使用 FireGuard 已有的 Blender GLB 建筑资产；点击车间或“进入车间”后显示该车间平面，且可返回工厂总览。
7. Copilot 不再把 JSON 下载作为主要用户动作。主动作改为“查看运行记录”，在页面内显示输入、证据、工具调用、人工确认和结果；“下载原始 JSON”放在次级位置。
8. “网格待办”改为“整改待办”，页面说明它是巡查隐患派给车间责任人的整改任务；空状态提供“去防火巡查新建任务”。
9. “AI 分析报告”改为“消防健康报告”，说明它用于风险评分后或周期复盘；没有评分数据时先引导导入/使用演示数据，不生成空洞报告。
10. 桌面端和 390px 移动端无横向溢出，主要按钮可键盘聚焦，切换控件使用可识别的选中状态。

## 后续里程碑

### M2：工艺化空间与档案录入

- 工厂总览 → 建筑 → 楼层 → 点位四级空间导航。
- 电池、涂装、总装、立体仓库、冲压车间分别使用不同工艺布局和风险点。
- 平面采用结构化场景与交互图层，不把风险点烘焙在图片里；报警可闪烁、高亮并打开证据卡。
- 企业档案提供“档案维护”入口，录入地址、楼层、危险源、出入口、水源、消防设施和设备点位；公网演示保存在浏览器，后端模式写入数据库。

### M3：巡查视觉识别

- 图片模型只输出隐患候选、位置、置信度和缺失信息，不直接派单。
- 低置信度必须拒答或转人工；派发前必须人工确认。
- 建立带标签的演示测试集，报告准确率、召回率、误报率和拒答率；没有评测结果前不得宣称准确率。

### M4：Copilot 全流程评委演示

- 一键演示覆盖：数据接入 → 风险检查 → 巡查识别 → 整改闭环 → 火警信号 → 人工核实 → 派单 → 班组反馈 → 归档 → 健康报告。
- 同一页面持续显示当前步骤、AI 做了什么、人工做了什么和生成了什么业务结果。
- 演示可自动播放；涉及核实、派单、归档的步骤明确标注“演示中的人工确认”，不伪装为真实自动决策。

## Boundaries

- 当前所有业务数据均为合成数据。
- 公网演示不连接 119、真实消防设备或真实调派系统。
- AI 不替代火情核实、现场指挥、派单批准和最终归档。
- M1 不接入真实视觉模型，不重做 PPT 或视频。
- 复用 FireGuard 同一项目体系中的 Blender 建筑资产，不合并政府监管与 119 指挥业务。
